# Management Task: 4 Hour Web Development Hackathon Plan

**Event name:** WebSprint
**Organised by:** GDGoC IET DAVV
**Format:** Offline, teams of 2 to 4
**Duration:** 4 hours

## 1. Objective and Theme

**Objective:** Give students, especially first and second years, a real experience of building something under time pressure, working in a team, and presenting their work. The focus is on learning and finishing a working product, not on perfect code.

**Theme: "Fix Your Campus"**
Teams build a small web app that solves a real problem around our college. Example ideas:
- Lost and found board for the campus
- Canteen menu and wait time tracker
- Notes and previous year papers sharing page
- Club events calendar

A fixed theme keeps every team focused and makes judging fair.

## 2. Event Schedule

| Time | Phase | What happens |
|---|---|---|
| 0:00 – 0:15 | Opening | Welcome, theme reveal, rules, Wi-Fi details, mentor introductions |
| 0:15 – 0:45 | Ideation | Teams pick a problem and plan features. Mentors check every team's idea so nobody picks something too big |
| 0:45 – 3:00 | Development | Building time. Check-in by mentors at the 1:30 mark to help stuck teams |
| 3:00 – 3:15 | Submission | Teams submit their GitHub link, live link (if any) and a short README. Submissions close sharp at 3:15 |
| 3:15 – 3:50 | Judging | Each team gets 3 minutes to demo plus 2 minutes of questions |
| 3:50 – 4:00 | Results | Winners announced, feedback form shared, group photo |

## 3. Resource Allocation

**Organising team roles**

| Role | People | Responsibility |
|---|---|---|
| Event lead | 1 | Overall coordination and timekeeping |
| Registration desk | 2 | Check-in, team verification, ID cards |
| Tech support | 2 | Wi-Fi, power sockets, projector, laptop issues |
| Mentors | 3 to 4 | Help teams with code and ideas (seniors or GDGoC core members) |
| Social media | 1 | Photos, updates and posts during the event |

**Mentors:** One mentor for every 4 to 5 teams. Mentors move around during development time and do not write code for teams.

**Technical infrastructure**
- College Wi-Fi plus 2 mobile hotspots as backup
- Extension boards at every table
- Projector and HDMI cable for demos
- Teams bring their own laptops
- Tools allowed: VS Code, GitHub, any free hosting (GitHub Pages, Netlify, Vercel), Firebase

**Judging panel:** 3 judges, for example one faculty member and two seniors or industry people with web development experience.

## 4. Rules and Guidelines

**Participation**
- Teams of 2 to 4 members. Solo entries are not allowed.
- All coding must start after the theme is revealed. Pre-built projects lead to disqualification.
- Templates and libraries are allowed, but they must be mentioned in the README.
- Every member must be present for the demo.

**Submission format**
- Public GitHub repository link
- README with problem, solution, features and how to run
- Live link (optional, but gives bonus points)

**Evaluation criteria**

| Criteria | Marks |
|---|---|
| Problem and idea (is it real and useful?) | 25 |
| Working features | 30 |
| UI and user experience | 20 |
| Code quality and README | 10 |
| Presentation | 15 |
| **Total** | **100** |

## 5. Contingency Planning

| Risk | Solution |
|---|---|
| Wi-Fi goes down | Backup hotspots ready; teams can keep coding offline and push later. Submission window extended if the problem is on our side |
| Power cut or laptop dies | Spare extension boards and chargers at the help desk; 2 spare laptops arranged if possible |
| A team is stuck or falling behind | Mentor check-in at 1:30; mentors help them cut down to the 2 or 3 features they can finish |
| Event running late | Strict timekeeper; demo time is fixed at 3 + 2 minutes; judges score on a shared sheet live |
| Fewer participants than expected | Allow teams of 2, accept spot registrations on the day |
| Plagiarism or pre-built project | Check GitHub commit history; all commits must be after the start time |
| Participant needs help (health, any issue) | Volunteers at the help desk; first aid kit available; contact numbers shared at the start |
